# MR Fire Safety Training Simulator

A mixed-reality training prototype that projects a burning virtual server rack onto the user's real
floor through passthrough, and lets them extinguish it with a controller acting as a virtual
extinguisher. Built as a master's thesis project.

Unlike fully immersive VR, the trainee is never transported elsewhere: the virtual prop is added to
their own room, so spatial awareness and the physical training ground are preserved.

| | |
|---|---|
| **Engine** | Unity 6000.3.21f1 LTS, URP 17.3, Single Pass Instanced |
| **XR stack** | OpenXR 1.17 + AR Foundation 6.6 + Meta OpenXR 2.5 |
| **Target** | Meta Quest 3 / 3S / Pro — Android, ARM64, Vulkan |
| **Performance target** | Sustained 72 FPS |

## Getting started

1. Open the project with Unity **6000.3.21f1** (other versions will re-serialize assets).
2. Open `Assets/_Project/Scenes/FireTraining.unity`, or regenerate it from the menu:
   **MR Fire Safety → Build Training Scene**. Generation wires every dependency, creates the
   `FireTarget` layer, and registers the scene as the first build entry.
3. Build to an Android device: **File → Build Settings → Android → Build and Run**.

Editor play mode shows the scene without passthrough or floor tracking — both require a device build.
`MrReadinessValidator` logs what is missing at startup.

## Running the tests

From the Editor: **Window → General → Test Runner**.

Headless:

```bash
Unity.exe -batchmode -nographics -projectPath . -runTests -testPlatform EditMode -testResults editmode.xml -logFile edit.log
```

- **EditMode** — the cellular-automata fire model and metric serialization, no scene required.
- **PlayMode** — the full training cycle: ignition, timed damage accumulation, suppression, and
  session reporting.

## Project structure

```
Assets/_Project/
├── Art/Materials/        URP materials generated by the scene builder
├── Input/                OpenXR controller action map
├── Scenes/               FireTraining.unity — the MR training scene
├── Scripts/
│   ├── Analytics/        Session metrics, JSON reports, device and frame-rate profiling
│   ├── Core/             AR session bootstrap, spatial awareness, anchoring, input, orchestration
│   ├── Editor/           Scene generator
│   ├── Fire/             Cellular-automata fire model, damage, visuals
│   ├── Suppression/      Raycast and particle agent paths, reservoir management
│   └── UI/               Training HUD and session presenters
└── Tests/                EditMode and PlayMode suites
```

Each subsystem is a separate assembly definition; dependencies point one way only
(`Fire → Suppression → Analytics → Core / UI`).

## Controls

| Control | Action |
|---|---|
| Right trigger | Discharge extinguishing agent — spends agent whether or not you hit |
| Right controller pose | Aim the extinguisher nozzle |
| **B** (right secondary) | Start the next run after a session ends |

The session starts by itself once the prop is anchored on the detected floor.

## Session data

Each run writes one JSON report to
`Application.persistentDataPath/SessionReports/session_<UTC timestamp>.json`, containing duration,
agent consumed, remaining object integrity, final fire intensity, frame-rate telemetry against the
device refresh rate, and an outcome field.

Outcomes are `Suppressed`, `AgentDepleted`, `ObjectDestroyed`, or `Interrupted`. A run interrupted by
removing the headset is still saved so the data is not lost, but **filter those out before comparing
performance** — they are incomplete by definition.

On Quest, pull them with:

```bash
adb pull /sdcard/Android/data/com.unideb.mrfiresafety.MRFireSafetySimulator/files/SessionReports
```

## Status

Implemented and passing tests (EditMode 10, PlayMode 6): spatial tracking, anchoring, controller
input, fire simulation, suppression with trigger-based agent consumption, session lifecycle with
outcomes and restart, analytics, gaze-following HUD, and the generated MR scene.

The fire model is calibrated by measurement rather than by feel — see
[Technical Architecture Document §3.3](Docs/TechnicalArchitectureDocument.md). A well-executed run
lasts about 48 s and consumes roughly 4 of the 10 agent units. `FireModelSweepTests` regenerates the
calibration table if the model is retuned, and `TrainingSceneBudgetTests` guards the content budget
(444 triangles, 20 renderers, no shadow-casting lights).

Pending, and only doable on hardware: deployment to a headset, confirmation that plane detection and
anchoring behave in a real room, tuning the HUD follow thresholds for personal comfort, and
profiling to confirm the 72 FPS target. Static budgets cannot establish a frame rate.
